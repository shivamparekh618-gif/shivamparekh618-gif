# Hi, I'm Shivam 👋

I like taking messy operational data and turning it into a decision someone can act on this week: which orders to chase, which queue to staff, and what to leave alone.

Most of my projects follow the same pattern. Clean the data honestly, match or aggregate it with SQL, rank what matters, and put it on one page a manager could actually use. Every README walks through one real decision the analysis supports, plus the questions I'd ask users before deploying it.

### Projects

**[Restaurant Order Reconciliation](https://github.com/shivamparekh618-gif/restaurant-order-reconciliation)**. Python + SQL
Matches delivery-platform orders against a restaurant POS, even when staff type the order ID wrong or leave it blank. It flags orders that never reached the kitchen, cancellations that weren't voided and menu prices that drifted apart, then ranks them by dollars at risk. On the sample data it traces 141 small price mismatches to a single stale menu price worth about $6k a year.

**[NYC 311 Backlog Triage](https://github.com/shivamparekh618-gif/nyc-311-backlog-triage)**. Python + SQL + NYC Open Data
Sorts 311 complaint queues into *growing*, *chronic* and *healthy*, and finds the week a queue started falling behind. The point is to tell a team lead where to focus and, just as important, which scary-looking backlog to leave alone.
